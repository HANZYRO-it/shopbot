# 🛍 Telegram-бот магазина — полная инструкция

> **ВАЖНО (версия «free»):** данные магазина теперь хранятся в **PostgreSQL** (а не в файле SQLite).
> Это позволяет запускать бота **бесплатно и без банковской карты** на Render + Neon — см. **`DEPLOY_FREE.md`**.
> Всюду ниже, где упоминается `data/shop.db` или `DB_PATH`, читайте «база PostgreSQL по `DATABASE_URL`».
> Для запуска нужна переменная `DATABASE_URL` в `.env`.

Бот для продажи вещей: каталог с фото, корзина, оформление заказа, уведомления,
админ-панель прямо в Telegram (товары, цены, остатки, заказы, рассылка, бэкапы).
Работает на сервере 24/7 — **ваш ПК для этого включённым быть не должен**.

---

## 1. Что умеет бот

**Покупатель**
- Каталог по категориям, карточка товара с фото, описанием, ценой и остатком
- Корзина (+ / − / удалить / очистить), контроль остатков
- Оформление заказа: имя → телефон (можно кнопкой) → адрес → комментарий → подтверждение
- «Мои заказы» со статусами, отмена заказа, пока он «Новый»
- Уведомление, когда магазин меняет статус заказа
- «О магазине»: контакты, условия оплаты и доставки

**Администратор** (команда `/admin`)
- Добавление / редактирование / скрытие / удаление товаров и категорий (с фото)
- Заказы: фильтры, карточка заказа, смена статуса (Новый → Подтверждён → Отправлен → Выполнен / Отменён).
  Клиент получает уведомление; при отмене товары автоматически возвращаются на склад
- Мгновенное уведомление о каждом новом заказе
- Рассылка всем пользователям (текст или фото)
- Статистика
- Бэкап базы: кнопка «💾 Бэкап базы» + автоматическая отправка файла базы вам в Telegram раз в сутки

> ⚠️ **Онлайн-оплаты в боте нет.** Оплата — при получении или переводом по реквизитам
> (текст задаётся в `PAYMENT_INFO`). Подключение карты (Stripe, ЮKassa и т. п.) — отдельная доработка.

## 2. Что понадобится (подготовка, ~10 минут)

### 2.1. Токен бота
1. В Telegram откройте **@BotFather** → команда `/newbot`.
2. Придумайте название и username (должен заканчиваться на `bot`).
3. BotFather пришлёт токен вида `123456789:AAE...` — **это пароль от бота, никому его не показывайте**.
   Если токен утёк — в @BotFather: `/revoke`.
4. По желанию: `/setuserpic` (аватар), `/setdescription` (описание), `/setabouttext`.

### 2.2. Ваш Telegram ID
Напишите боту **@userinfobot** — он ответит числом (`Id: 123456789`). Это ваш `ADMIN_IDS`.
Второго админа можно добавить через запятую: `111111,222222`.

### 2.3. Сервер (VPS) — чтобы бот работал без вашего ПК
Нужен небольшой виртуальный сервер с **Ubuntu 22.04 / 24.04** (1 ядро, 1 ГБ ОЗУ хватает с запасом).
Подойдёт любой хостинг: Hetzner, Contabo, Netcup, Timeweb Cloud, DigitalOcean и т. п.
Ориентировочно 3–6 € в месяц (цены меняются — смотрите на сайте провайдера).

При создании сервера выберите Ubuntu, и вам пришлют **IP-адрес** и **пароль для root**
(или вы загрузите свой SSH-ключ).

> Бесплатные варианты есть, но они ненадёжны (засыпают, удаляют данные). Для магазина лучше платный VPS.
> Альтернатива: Raspberry Pi / старый ноутбук дома, который не выключается, — установка та же.

## 3. Установка на сервер (рекомендуемый способ — одной командой)

### Шаг 1. Загрузите папку проекта на сервер
**Windows 10/11, macOS, Linux** — откройте терминал (Windows: *PowerShell*), перейдите в папку,
где лежит папка `telegram-shop-bot`, и выполните (замените `IP` на адрес сервера):

```bash
scp -r telegram-shop-bot root@IP:/opt/
```
Введите пароль root. (Можно и через программу WinSCP / FileZilla — просто скопируйте папку в `/opt/`.)

### Шаг 2. Подключитесь к серверу
```bash
ssh root@IP
```

### Шаг 3. Запустите установщик
```bash
cd /opt/telegram-shop-bot
sudo bash install.sh
```
Скрипт сам:
1. установит Docker (если его нет),
2. спросит **токен**, **ваш ID**, **название магазина** и **валюту**, создаст файл `.env`,
3. соберёт и запустит бота так, что он **сам перезапускается при сбоях и после перезагрузки сервера**.

### Шаг 4. Проверьте
```bash
docker compose logs -f
```
Должна появиться строка `Бот запущен: @имя_вашего_бота` (выйти из логов — `Ctrl+C`, бот продолжит работать).

Теперь можно закрывать терминал и выключать ПК — бот работает на сервере. ✅

## 4. Первый запуск и наполнение магазина

1. Откройте своего бота в Telegram и нажмите **/start**.
   (Важно: админ должен хотя бы раз нажать /start, иначе бот не сможет присылать ему уведомления.)
2. Отправьте **/admin** (или кнопка «⚙️ Админ-панель» в меню).
3. **Категории → ➕ Новая категория** (например «Куртки»).
4. **➕ Добавить товар** → выберите категорию → название → цена → описание → остаток → фото.
5. Откройте бота «глазами покупателя»: Каталог → товар → В корзину → Оформить заказ.
6. Вам придёт уведомление о заказе с кнопками смены статуса.

Цены вводятся как `1500` или `19.99`. Остаток `0` = «нет в наличии».
Скрытый товар (🙈) не виден покупателям, но остаётся в базе.

## 5. Настройки (файл `.env`)

Редактирование: `nano /opt/telegram-shop-bot/.env`, затем применить: `docker compose up -d --build`.

| Переменная | Что делает |
|---|---|
| `BOT_TOKEN` | Токен от @BotFather (обязательно) |
| `ADMIN_IDS` | ID админов через запятую (обязательно) |
| `DATABASE_URL` | Строка подключения к PostgreSQL, например от Neon (обязательно) |
| `SHOP_NAME` | Название магазина в приветствии |
| `CURRENCY` | Символ валюты: `€`, `₴`, `$`, `₽` … |
| `CONTACTS` | Контакты в «О магазине» (перенос строки — `\n`) |
| `PAYMENT_INFO` | Условия оплаты/доставки — показываются после заказа |
| `TIMEZONE` | Часовой пояс дат, например `Europe/Berlin` |
| `BACKUP_HOURS` | Раз в сколько часов присылать файл-бэкап (0 — выключить) |
| `WEBHOOK_URL` | Только для хостинга без постоянного процесса. На Render задаётся сам; локально оставьте пустым |

Не используйте символ `#` в значениях (он начинает комментарий).

## 6. Повседневное управление

```bash
cd /opt/telegram-shop-bot
docker compose logs -f          # смотреть логи
docker compose restart          # перезапустить
docker compose down             # остановить
docker compose up -d --build    # применить изменения .env / обновить код
```

### Обновление кода
Замените папку `shopbot` на новую версию (через `scp` или WinSCP), затем `docker compose up -d --build`.
Файл `.env` не трогается, а данные лежат во внешней базе PostgreSQL и обновлением кода не затрагиваются.

### Резервные копии (важно!)
Все данные магазина — в базе PostgreSQL (`DATABASE_URL`).
- **Автоматически:** бот раз в `BACKUP_HOURS` часов присылает админам в Telegram файл `shop-….json`
  (время последней отправки хранится в базе, перезапуски сервера расписание не сбивают).
- **Вручную:** `/admin` → «💾 Бэкап базы».
- **Восстановление:** на компьютере с настроенным `.env` выполните
  `python -m shopbot.restore путь\к\shop-….json` — текущие данные будут **полностью заменены** содержимым файла.
- Фото товаров хранятся на серверах Telegram (в базе только ссылки на них), поэтому в бэкапе их нет,
  но при восстановлении они продолжают работать с тем же ботом.
- Дополнительно у провайдера базы (Neon) есть собственная короткая история изменений — смотрите их настройки.

### Перенос на другой сервер
Скопируйте папку проекта целиком (вместе с `.env`) и снова выполните `sudo bash install.sh`. База не переезжает — она во внешнем PostgreSQL.

## 7. Запуск без Docker (альтернатива)

```bash
sudo apt update && sudo apt install -y python3 python3-venv
cd /opt/telegram-shop-bot
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
cp .env.example .env && nano .env              # впишите токен и ID
sudo useradd -r -s /usr/sbin/nologin shopbot
sudo chown -R shopbot:shopbot /opt/telegram-shop-bot
sudo cp deploy/shopbot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now shopbot
journalctl -u shopbot -f                       # логи
```

## 8. Проверка на своём ПК (по желанию)

Нужен Python 3.10+. В папке проекта:
```bash
python -m venv venv
venv\Scripts\activate            # Windows  (Linux/macOS: source venv/bin/activate)
pip install -r requirements.txt
copy .env.example .env           # Linux/macOS: cp .env.example .env
# впишите BOT_TOKEN, ADMIN_IDS и DATABASE_URL в .env
python -m shopbot
```
Пока окно открыто — бот работает; закроете окно или выключите ПК — остановится.
Для постоянной работы используйте сервер (раздел 3).
**Не запускайте одновременно локально и на сервере с одним токеном** — будет конфликт.
Если бот уже работает на Render (webhook), локальный запуск **снимает вебхук**, и бот на Render замолчит,
пока вы не перезапустите его там (Render → Manual Deploy → Restart).

## 9. Если что-то не работает

| Симптом | Решение |
|---|---|
| Бот не отвечает | `docker compose logs --tail 50` — смотрите ошибки. Проверьте `BOT_TOKEN` |
| `DATABASE_URL не задан` / `Не удалось подключиться к базе` | Вставьте строку подключения из Neon целиком в `.env` (см. `DEPLOY_FREE.md`) |
| `BOT_TOKEN не задан` / неверный формат | Откройте `.env`, вставьте токен целиком, без кавычек и пробелов |
| Нет кнопки «Админ-панель», `/admin` молчит | Ваш ID не в `ADMIN_IDS` (проверьте через @userinfobot), после правки: `docker compose up -d --build` |
| Не приходят уведомления о заказах | Админ должен один раз нажать /start у бота |
| `Conflict: terminated by other getUpdates request` | Тот же токен запущен ещё где-то (ПК, другой сервер). Остановите лишний экземпляр |
| Фото не показываются | Отправляйте фото как изображение (не как файл) |
| После перезагрузки сервера бот не поднялся | `docker compose ps`; Docker включён: `sudo systemctl enable --now docker` |

## 10. Безопасность

- Не публикуйте `.env` и токен (в проект уже добавлен `.gitignore`).
- Для сервера лучше SSH-ключ вместо пароля, а также `sudo apt update && sudo apt upgrade` раз в месяц.
- База содержит имена, телефоны и адреса клиентов — это персональные данные. Если вы продаёте в ЕС,
  учитывайте требования GDPR (политика конфиденциальности, срок хранения, удаление по запросу).

## 11. Структура проекта

```
telegram-shop-bot/
├── install.sh            # установка на сервер одной командой
├── Dockerfile, docker-compose.yml
├── .env.example          # шаблон настроек
├── DEPLOY_FREE.md        # бесплатный запуск без карты (Render + Neon)
├── requirements.txt
├── deploy/shopbot.service  # systemd (вариант без Docker)
└── shopbot/
    ├── main.py           # запуск (webhook на хостинге / polling локально)
    ├── config.py         # настройки из .env
    ├── db.py             # база PostgreSQL (товары, корзина, заказы)
    ├── fsm_storage.py    # шаги диалогов хранятся в базе
    ├── restore.py        # восстановление из JSON-бэкапа
    ├── keyboards.py      # кнопки
    ├── utils.py          # цены, тексты
    ├── notify.py, backup.py, middleware.py
    └── handlers/         # common.py, user.py (покупатель), admin.py (админ)
```
